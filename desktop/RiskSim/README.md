# RiskSim Desktop

Нативное macOS-приложение на SwiftUI. Electron и обязательный браузер не используются.

## Запуск

```bash
cd /Users/asan_97kglist.ru/risk-sim/desktop/RiskSim
scripts/build_app.sh
open dist/RiskSim.app
```

Требуется Python-окружение проекта в `/Users/asan_97kglist.ru/risk-sim/.venv` и
Blender из Steam. Пути можно изменить в настройках приложения.

## Проверка

```bash
swift test
```

Тесты проверяют пути, запуск Python CLI, декодирование `scene_bundle.json`
(включая Monte Carlo, агентов и сводку нарушений), загрузку модели приложения
и новый pilot-расчёт во временной папке.

## Архитектура

```text
SwiftUI (нативный интерфейс)
  → Python CLI (расчёты, MuJoCo, Monte Carlo, IFC)
  → scene_bundle.json / отчёты
  → Blender (3D и рендер)
```

Реализованы: запуск пилота (полный и быстрый) с потоковым журналом и отменой,
импорт IFC, **клиренс грузового пути против 3D-модели** (свип груза/стрелы/башни
по мешу `model.glb`, допуск 0.5 м, события в конфликтах и на Обзоре),
метрики, конфликты с фильтром по критичности и поиском,
подъёмы с нарушениями и безопасными окнами по ветру, 2D-план площадки
(зоны, кран, грузы, воспроизведение), таймлайн с плеером, PDF/DOCX,
реалистичное видео в Blender (Cycles/Metal), открытие Blender и OpenUSD,
настройки путей с автосохранением.

## Реалистичный Blender-ролик

`blender/scene_realistic.py` строит фотореалистичную сцену из `scene_bundle.json`:
башня с остеклёнными этажами до земли, решётчатый башенный кран с оттяжками
и противовесом, ярус работ с опалубкой и ограждениями, фигуры бригад с касками,
PBR-материалы. Солнце и небо (SINGLE_SCATTERING) считаются алгоритмом NOAA по
реальному времени таймлайна — тени едут по неделе работ, ночью солнце гаснет.
Аниматор `animate_realistic.py` ведёт кран по кадрам расчёта (поворот/вылет/
высота), груз качается на маятнике из MuJoCo-раскачки, зоны подсвечиваются
в окна нарушений. Рендер: `make realistic` (или кнопка «Реалистичное видео»
на странице «Отчёты»), Cycles на Metal.

## Инженерная точность (сертификат сцены)

`blender/validate_scene.py` — обязательный шаг конвейера (шаг 3/5): измеряет
мировые координаты объектов прямо в Blender и сверяет их с числами расчёта.
Допуски и факт (sample-сценарий, 11 кадров):

| Метрика | Допуск | Факт | Роль |
|---|---|---|---|
| Ось поворота крана | 20 мм | 0.0 мм | гейт |
| Угол поворота стрелы | 0.5° | 0.0° | гейт |
| Радиус тележки | 5 см | 0.0 м | гейт |
| Высота крюка (hook_z_m) | 5 см | 0.0 м | гейт |
| Позиция груза (x,y,z) | 5 см | 0.0 м | гейт |
| Длина троса крюк-кольцо | 5 % | 0.0 % | гейт |
| Азимут/высота солнца (NOAA) | 0.5° | 0.0° | гейт |
| Маятниковый снос груза | 25 % | 23.6 % | info* |

Итог пишется в `results/dynamics/scene_validation.json` (кадровая детализация +
вердикт PASS/FAIL по гейтам). При FAIL рендер отменяется. Высота кольца строп
берётся из паспортного угла строп `sling_included_angle_deg`, трос и крюк —
из `hook_z_m`, наклон груза — из `swing_theta_deg` MuJoCo-раскачки.
\* маятниковый снос — информационная метрика: при режиме `moving_anchor`
горизонтальный снос крюк→груз включает перенос якоря, поэтому tan(θ) не обязан
совпадать с измеренным сносом; позиция груза при этом проверяется точно.

Внутри `crane_scene.blend`: панель **RiskSim** (N-панель: камеры, слои, переход
к подъёмам), текст `КАК_ПОЛЬЗОВАТЬСЯ.txt`; файл открывается в дневном кадре
с видом из камеры. Все 4 типа грузов строятся сразу — аниматор переключает
нужный по `lift_id`; ветроконус калиброван 1.5–9 м/с, шкалы ветра показывают
порывы против пределов крана из JSON.

## Горячие клавиши

- ⌘R — полный расчёт пилота
- Space — плей/пауза таймлайна (на страницах «План» и «Таймлайн»)
