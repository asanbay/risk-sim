# План пилота: 8 недель (v1.1, 2026-11-02)

Принципы из спецификации, которые не обсуждаются:
1. **Каждую неделю — демонстрируемый артефакт.** Неделя без демо = неделя впустую.
2. **До недели 5 никакого визуального полирования.** Сначала цифры и доверие к ним.
3. **Всё должно работать на MacBook заказчика.** Тяжёлое (Cycles, OpenFOAM) — опционально в облаке.
4. **JSON — единственный контракт** между ядром и визуализацией: рендереры заменяемы.
5. **Система не заменяет расчёт по нормам.** Каждый артефакт несёт дисклеймер.

недели 5–8 идут по плану ниже с заделом (viewer, Blender-слой, панель и PDF уже работают).

## Неделя 5 — отчёты и панель (полировка по замечаниям)
* Фиксация формулировок двух метрик экспозиции (консервативная/измеренная) во всех artefact'ах.
* Проверка читаемости: GIF ≤ 2 МБ, PDF ≤ 1 МБ, отчёт открывается офлайн.
* Приёмка: замечания заказчика недели 5 закрыты без изменения контрактов.

## Неделя 6 — 3D
* `blender/render.sh` на Mac: EEVEE Next 1280×720 (черновик), Cycles — только по решению.
* `viewer/pilot_three.html` с glb: скраббер таймлайна, подсветка зон нарушений.
* Запасной вариант без Blender: GIF + офлайн viewer (уже есть).

## Неделя 7 — реальные данные и IFC
* Замена data/sample на выдержку ППР: подъём с цифрами, лимит ветра, схема строповки.
* IFC (IfcOpenShell): геометрия импортируется в GLB, Three.js и Blender;
  зоны/уровни для правил подтверждаются отдельно в CSV, автоматический вывод зон не выполняется.
* Переверификация V1–V11 на новых входах; отчёт «что изменилось против sample».

## Неделя 8 — опытная эксплуатация и решение о тиражировании
* Инструктаж бригад: ролик недели + панель на планёрке; сбор замечаний.
* Отчёт пилота: принятые/отклонённые рекомендации, эффект по чел·мин, ограничения.
* Решение: тираж / доработка / остановка. OpenFOAM-CFD и PyChrono — только как
  отдельные облачные задачи вне MacBook, если пилот признан успешным.
