# Методика расчёта (версия 0.7, 2026-11-04)

Документ объясняет, **что именно считает ядро и почему**, и где границы
применимости. Это не нормативный документ: допустимые значения берутся из ППР
и паспортов оборудования, а результат симуляции — поддержка решений,
а не расчёт по нормам.

## 1. Ветер

* Средняя скорость на высоте z: степенной профиль ESDU/Eurocode
  `v(z) = v_ref · (z / z_ref)^α`, α = 0.16 (открытая местность, по rules.yaml),
  z_ref = 10 м. Интенсивность турбулентности Iu(z) спадает с высотой —
  проверяется тестом V8b.
* Порывы: модель Дурста (gust factor через Iu и длительность усреднения),
  режим `wind_gust_policy: measured` — при наличии измеренного ряда wind.csv
  берутся фактические порывы, модель используется только для интерполяции
  между высотами и заполнения пропусков (тест V8d: интерполяция корректна
  по времени).
* Экстраполяция ограничена `wind_extrapolation_max_ratio` (не выше 8×z_ref),
  выше — предупреждение и консервативное продолжение профиля.

## 2. Ветровая нагрузка на груз и кран

`F = 0.5 · ρ(z) · Cd · A · v(z)²`, где:
* ρ(z) — барометрическая модель плотности воздуха (V3);
* Cd — диапазон [1.1, 1.6] по rules.yaml, в Monte Carlo тянется из диапазона;
* A — парусность груза из lifts.csv (паспортная, не расчётная);
* v — порыв на высоте груза (не средняя!).
Динамический коэффициент 1.1/1.2/1.35 (плавный/обычный/резкий пуск) — из ППР.

## 3. Раскачка груза (маятник)

Груз на подвесе длины L моделируется как сферический маятник с возбуждением
ветровой силой F(t) и демпфированием таглайна/сопротивления:
* аналитика: малые углы, `θ̈ + 2ζωθ̇ + ω²θ = F/(m·L)`, ω = √(g/L);
* MuJoCo: полная нелинейная модель (кватернионы), используется для
  верификации аналитики (V4, V7: период/смещение/RMS расходятся < 3–5%);
* статическое отклонение `x = F·L/(m·g)` — ручной расчёт V5.
Знак кватерниона в MuJoCo сверен с аналитикой (фаза без зеркалирования).

В режиме `moving_anchor` точка подвеса движется по фазам ППР:
`rig → hoist → travel → position → lower → unhook`.
Положение груза, инерция, относительная скорость воздуха и оттяжка вычисляются
на каждом шаге MuJoCo. При `collision_geometry` добавляются перекрытия и ядро
здания как collision-боксы; для каждого контакта сохраняются имя, интервал,
глубина и максимальная нормальная сила. Контакт — событие движка, а не вывод
об аварии: размеры и допустимые касания подтверждает инженер.

## 4. Такелаж

* Натяжение ветви стропа: `S = Q/(n·sin α)` с ограничением включённого угла
  ≤ 90° и примечанием о дерейтинге производителя (rules.yaml);
* оттяжка (таглайн): допустимое усилие на человека 200 Н (пик 400 Н),
  эффективность 0.7, не более 4 человек; дефицит = F_ветра − способность;
* использование грузоподъёмности крана — по load_chart (радиус → кг),
  интерполяция монотонно убывающая (регрессия V-тестов).

## 5. Расписание и люди

* Задачи/зоны/бригады — из works.csv, zones.csv, crews.csv;
* агентная симуляция: маршруты по зонам, состояния working/transit/break,
  отклонения скорости (σ = 0.25 м/с) и задержки — Monte Carlo графика;
* метрика экспозиции: чел·мин пребывания в зоне активного нарушения
  (под грузом, у края без ограждения, в проходе, в зоне двух бригад);
* вероятность события = доля прогонов MC с событием (V9b).

Две метрики экспозиции используются сознательно и не должны смешиваться:
* **консервативная** (findings): окно правила × все люди задействованных зон —
  верхняя оценка для резерва решений;
* **измеренная** (агентные треки): фактическое присутствие людей по шагам симуляции —
  оценка для планирования смен и инструктажей.
Разница между ними — запас безопасности, а не расхождение моделей; обе печатаются
в отчёте с явными подписями.

## 6. Правила

11 правил (rules.yaml), каждое с полем `source` — ссылка на ППР/паспорт/норму.
Правило без источника отбраковывается на старте (V11c): в пилоте нельзя
«изобретать» нормы кодом.

## 7. Monte Carlo

* подъёмы: N=5000 прогонов (порывы, Cd, пуск), вероятности нарушений и
  кривая безопасного ветра (v_ref → P(нарушение));
* график: N=2000 прогонов (длительности логнормальные, задержки), P(пара
  бригад/работ друг над другом), p95 чел·ч экспозиции;
* воспроизводимость: фикс-seed 42 (V9).

## 8. Что НЕ моделируется (границы применимости)

* аэродинамика здания (вихри, ускорение потока у фасада) — только облачный
  OpenFOAM, в пилоте консервативный профиль;
* упругость стрелы/полиспаста, колебания мачты крана;
* поведение людей (реакция на сигнал, дисциплина) — только маршруты;
* IFC-геометрия импортируется через IfcOpenShell в GLB с проверкой единиц и хэшей;
  рабочие зоны, маршруты и правила по-прежнему задаются отдельно в CSV/YAML,
  автоматического вывода зон из IFC нет;
* температура/обледенение/гроза — вне скоупа пилота.
